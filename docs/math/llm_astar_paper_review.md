# LLM-A*: paper review and implications for Viktor

Reviewed: 2026-10-03. Research only; no implementation or experimental reproduction.

**Paper:** Silin Meng, Yiwei Wang, Cheng-Fu Yang, Nanyun Peng, and Kai-Wei Chang, “LLM-A*: Large Language Model Enhanced Incremental Heuristic Search on Path Planning,” Findings of EMNLP 2024, pp. 1087-1102. [Official publication record](https://aclanthology.org/2024.findings-emnlp.60/). Primary source read in full: `/home/barry/Downloads/2024.findings-emnlp.60.pdf`, including Appendices A-D. Page references below use printed proceedings numbers; PDF page = printed page minus 1086.

**Main finding:** LLM-generated waypoint suggestions can reduce the work performed by a conventional search algorithm on the tested static maps. The strongest reported configuration uses 44.59% of A*'s search operations and 64.02% of its search storage, with a relative path length of 102.47% and 100% reported benchmark validity. These are search metrics, not end-to-end latency, total system memory, or road-safety guarantees.

**Relevance to Viktor:** use learned scene understanding to guide a planner, while explicit geometry/dynamics checks determine whether its output is usable. This is an architectural lesson to test. The paper does not demonstrate camera-based driving, 20-30 ms operation, grounded structured reasons, or training a model from random initialization.

## 1. Problem definition

### What the paper computes

The inputs are a start point, a goal point, environment boundaries, and a known obstacle map. Obstacles are described using coordinates, including horizontal and vertical line barriers. A pretrained language model receives a textual description and proposes a sequence of waypoint coordinates. A modified A* search uses these points to bias which states it explores. The output is a geometric path.

The paper addresses a complementary weakness of two approaches:

- A* can expend substantial search work exploring states that a useful global route suggestion might avoid.
- An LLM can suggest a broad route but produce invalid detailed geometry when asked to output the path directly.

LLM-A* combines the suggestion with explicit search. The neural output is guidance, not an executable driving trajectory. Although the title says “incremental,” the paper's main increment is updating the target waypoint during a search; it does not demonstrate persistent replanning under moving obstacles in the manner of a dynamic driving system.

### Experiment design

Sections 4.1-4.2, p. 1092, describe 100 manually selected maps from a randomly generated collection. Each nominal 50 by 30 map has 10 start/goal pairs, giving 1,000 tasks. The spatial units are not identified as meters. The environment is described as continuous, but both algorithms operate on discrete points and actions.

The LLMs are GPT-3.5-Turbo and Llama 3 8B in 16-bit precision. This is prompting of existing models, not a new network architecture or a training-from-scratch study. Prompt variants are:

- Five-shot demonstrations: examples of environment descriptions and waypoint outputs.
- Three-shot chain of thought (CoT): examples with explanatory reasoning.
- Three-shot Recursive Path Evaluation (RePE): stepwise environment analysis, point selection, and self-evaluation. Section 3.3 explicitly says RePE receives no environment feedback; its evaluations are generated by the model itself.

The main baselines are ordinary A*, dynamic weighted A* with initial weight 2 and decay 0.99, and LLM-only path generation. The weighted baseline is relevant because LLM-A* also trades optimality for search efficiency without requiring an admissible heuristic.

The best search-efficiency result is Llama 3 with simple few-shot prompting. Its operation ratio corresponds to a 55.41% reduction, its storage ratio to a 35.98% reduction, and its path-length ratio to a 2.47% multiplicative excess. These are not arithmetic means of per-task absolute savings, worst-case bounds, or an end-to-end speedup.

Longer reasoning prompts do not improve search efficiency in this table. GPT-3.5 RePE yields a marginally better path-length ratio, 102.41% rather than 102.44% with few-shot, while its operation ratio rises from 57.39% to 85.47%. This comparison also changes demonstration count and prompt format, so it does not isolate reasoning length as the cause. The result supports testing concise guidance; it does not prove reasoning is unnecessary.

Direct LLM path generation achieves only 7.8%-16.4% validity across these settings. The hybrid obtains 100% on the tested tasks. This is evidence for retaining explicit search and constraint handling rather than trusting coordinate generation alone. The paper does not clearly specify how invalid LLM-only paths contribute to the path-length aggregate, so those lengths should not be interpreted as a complete usefulness score.

Figure 1, p. 1087, is one illustrative case: A* uses 859 operations and 802 storage units; LLM-A* uses 140 and 235; both paths have length 53.46. It shows a strong individual gain, not the dataset average. Figure 3, p. 1094, reports scaling trends from 10 random-sampling trials; it is not a proof of asymptotic complexity.

## 2. Assumptions

1. **Known, correct static geometry.** The paper supplies obstacle descriptions. Missing objects, uncertain camera depth, and changing traffic violate that input model and invalidate any direct collision-free interpretation for a real vehicle.
2. **A finite discretization for the search analysis below.** Reachability and runtime depend on the state graph, neighbor rules, and resolution. Continuous-state completeness does not follow from a finite-grid result.
3. **Compatible costs.** The paper's main intuition uses Euclidean distance. Edge cost, goal heuristic, and waypoint distance must share units and compatible geometry. Distance cannot be added directly to time, energy, or an unscaled risk score.
4. **Valid transitions.** Collision-free endpoint coordinates alone do not establish a collision-free connecting segment. For a vehicle, the swept footprint must also be checked. The pseudocode's obstacle test does not fully specify this geometry.
5. **Usable waypoint output.** Waypoints must be finite, interpretable in the map frame, and compatible with the discrete states or an explicit matching rule. Filtering points inside obstacles does not establish reachability, valid connecting segments, or an appropriate vehicle maneuver.
6. **Metric aggregation uses positive finite ratios.** Zero-length reference paths and failed runs require explicit handling rather than division by zero or arbitrary epsilon replacement.
7. **Latency break-even examples assume a timing model.** Proportionality between search-operation count and time is only a hypothetical approximation below. It is not an observed result from this paper.
8. **Viktor's requirements persist.** The target includes camera processing, fresh structured scene evidence, maneuver decision, reasons, and validated planning in the same 20-30 ms interval. Every learned component is to be trained from random initialization. Neither requirement was evaluated in the paper.

## 4. Derivation

### A. Ordinary A* and the waypoint modification

Ordinary A* combines the accumulated cost and an estimated remaining cost, $f(s)=g(s)+h(s)$. The shortest-path relaxation through an expanded state $u$ gives a candidate neighbor cost $g(u)+c(u,v)$; the parent and cost are updated if this improves the recorded value. A priority queue selects the state with smallest $f$.

LLM-A* adds a distance to the current suggested target, so states near that target become more attractive. Algorithm 1, p. 1090, and Section 3.2, p. 1091, give $f(s)=g(s)+h(s)+cost(t,s)$. The LLM is called to generate the target list before search. The method inserts missing start/goal points and removes target points inside obstacles.

When the algorithm switches targets, priorities for all current OPEN states are recomputed. This is a globally changing search-order bias, not a separate A* invocation for each waypoint segment. The pseudocode does not require the final reconstructed path to pass through every suggested waypoint.

### B. Why the shortest-path guarantee is lost

An admissible goal heuristic obeys $h(s)\le h^\star(s)$. A consistent heuristic additionally obeys $h(u)\le c(u,v)+h(v)$ on every edge. For ordinary graph-search A* that never reopens CLOSED states, consistency is the usual sufficient condition for optimality; admissibility alone needs suitable reopening and termination treatment.

Adding a nonnegative waypoint term does not preserve either inequality. On an obstacle-free straight line, take $s=(0,0)$, $s_g=(10,0)$, and $t=(5,0)$. The true remaining length is 10, but the combined estimate is $10+5=15$. Thus it overestimates.

If the current target becomes the goal and both terms are the same Euclidean distance, the formula becomes $f=g+2h$. This is a weight-2 heuristic at that stage, not ordinary A*. At $s=(0,0)$ and adjacent $v=(1,0)$, consistency would require $20\le1+18=19$, which is false. If the current target is not the goal, its contribution at the goal itself can be positive even though true remaining cost there is zero.

Appendix A, p. 1099, explicitly acknowledges non-admissibility, and the Limitations section, p. 1095, states there is no optimal-path guarantee. Its statement that around 90% of paths are optimal is an empirical observation, not a bound on the remaining cases. The dynamic target changes and no-reopening pseudocode do not inherit a general bounded-suboptimality theorem merely from resemblance to weighted A*.

### C. Search savings must exceed guidance overhead

For a comparison with identical common stages, plain planning takes $T_{\rm shared}+T_A$, while the hybrid takes $T_{\rm shared}+T_L+T_H+T_U$. Subtraction shows that the hybrid is faster precisely when added guidance and overhead cost less than the search time saved.

Only if measured guided search time can be approximated by $\rho T_A$ can this be rewritten using a ratio. Substituting the paper's operation ratio, $\rho=0.4459$, is an illustrative assumption, not a valid conversion from Table 1 to latency. Different queue operations, heuristic evaluation, batching, and memory behavior can change the relation.

The paper reports no camera-to-plan milliseconds, LLM token-generation timing, device-specific tail latency, or total model-plus-search memory. Its search savings therefore cannot establish that LLM-A* meets Viktor's deadline or even that the full pipeline is faster than A*.

### D. Interpreting complexity and aggregation

For an ordinary finite graph, a consistent heuristic and a binary-heap implementation give the familiar $O((\vertV\vert+\vertE\vert)\log \vertV\vert)$ search bound with appropriate decrease-key handling and $O(\vertV\vert)$ auxiliary state storage, excluding the graph representation. On a bounded-degree grid, $\vertE\vert=O(\vertV\vert)$. This is an illustrative implementation analysis, not a complexity theorem proved by the paper.

Changing all frontier priorities at target switch $j$ requires evaluating $\vertO_j\vert$ priorities. A complete heap rebuild can be linear in $\vertO_j\vert$; updating keys individually can instead introduce an extra logarithmic factor. Over switches, the overhead depends on $\sum_{j=1}^{J}\vertO_j\vert$, in addition to LLM inference. An operation count needs to specify whether and how it includes this work.

If both spatial dimensions scale by $a$ while cell size stays fixed, grid-state count grows on the order of $a^2$. At 10 times coordinate scale, this is about 100 times as many states. A rapidly bending curve against coordinate scale therefore does not demonstrate exponential complexity. Figure 3 provides empirical scaling evidence over the sampled maps; its exponential-versus-linear wording is stronger than the evidence supports.

For positive per-task ratios, taking logs turns the geometric mean product into an average. This is numerically preferable to multiplying many ratios and avoids intermediate product overflow/underflow. It does not bound the worst task, the worst latency, or failure probability.

## 5. Final equations

Paper search rule, with $d_t$ making the waypoint term explicit:

$$
\begin{aligned}
f_A(s) &= g(s)+h(s), \\
f_H(s) &= g(s)+h(s)+d_t(s), \\
d_t(s) &= \lVert s-t\rVert_2
\quad\text{for the Euclidean examples}.
\end{aligned}
\tag{R1}
$$

Relaxation on an allowed transition:

$$
\begin{aligned}
g_{\rm candidate}(v) &= g(u)+c(u,v), \\
g(v) &\leftarrow\min\{g(v),g_{\rm candidate}(v)\}.
\end{aligned}
\tag{R2}
$$

The paper skips CLOSED neighbors before relaxation. Equation R2 by itself does not supply the reopening logic needed for a general inconsistent-heuristic optimal search.

Admissibility and consistency conditions, respectively:

$$
\begin{gathered}
0\le h(s)\le h^\star(s), \\
h(u)\le c(u,v)+h(v),\qquad h(s_g)=0.
\end{gathered}
\tag{R3}
$$

Stable form of the paper's Appendix D Equation (1):

$$
\begin{aligned}
\log G_R &= \frac{1}{n}\sum_{i=1}^{n}
\left(\log m_i^H-\log m_i^A\right), \\
G_R &= \exp(\log G_R).
\end{aligned}
\tag{R4}
$$

For smaller-is-better metrics, the table reports $100G_R$, and the corresponding relative reduction is $100(1-G_R)$ percent. If the final exponential is not representable, retain the log aggregate rather than silently overflowing. Positive finite inputs and an explicit failure/zero-denominator policy are required.

Latency break-even, derived in this review:

$$
\begin{gathered}
T_L+T_U<T_A-T_H; \\
T_H=\rho T_A\quad\Longrightarrow\quad
T_L+T_U<(1-\rho)T_A.
\end{gathered}
\tag{R5}
$$

The additional deadline requirement is:

$$
T_{\rm shared}+T_L+T_H+T_U\le D.
\tag{R6}
$$

The common and extra stages must collectively include the complete camera-to-validated-plan critical path without omissions or double-counted overlapping stages. Faster-than-baseline and meeting the deadline are different conditions.

Conditional target-update complexity when each priority is constant-cost and the frontier heap is rebuilt:

$$
\begin{aligned}
W_{\rm update} &= O\!\left(\sum_{j=1}^{J}\lvert O_j\rvert\right), \\
\lvert V(a)\rvert &= \Theta(a^2)
\quad\text{for a fixed-resolution 2D grid}.
\end{aligned}
\tag{R7}
$$

R1-R3 use compatible cost units; R4 is dimensionless; R5-R6 compare times; R7 counts work/states. None supplies a vehicle-dynamics or collision-probability guarantee.

## 6. Constraints

### What validity would require

A path must connect the requested endpoints through valid transitions. Checking only that waypoint vertices avoid obstacle coordinates is insufficient: connecting segments can intersect barriers. For a vehicle, geometry also depends on body dimensions, heading, clearance, and uncertainty. A time-parameterized trajectory must additionally obey speed, acceleration, curvature, steering-rate, and other chosen dynamic limits while considering moving traffic.

These vehicle quantities are absent from the paper's formulation. There is no velocity state, lead-vehicle prediction model, following-distance objective, calibrated monocular-depth treatment, actuator model, or physical control law. No Nissan Leaf-specific limits should be inferred from this study.

### Consequences for Viktor's architecture

The useful transfer is the division of responsibility: learned guidance can suggest which admissible behaviors or routes to prioritize; a planner/validator evaluates actual feasibility. For the initial lane-keeping and following task, this could mean a compact model producing lane/lead evidence, a maneuver decision, reasons, and bounded planning guidance in the same forward pass, followed by bounded trajectory evaluation. This is a proposed adaptation, not a system tested in LLM-A*.

There is no evidence here that Viktor needs a full A* search in every highway cycle. Before adding it, compare the existing compact candidate-planning proposal with a geometry/dynamics baseline and a guided-search alternative. Highway following requires timing and lead-vehicle motion, which static global waypoints do not address. The appropriate planner remains an empirical and mathematical design choice.

For the required 20-30 ms interval, fresh scene reasoning must remain synchronous. Optional longer-horizon route guidance could be cached only with an explicit validity/age policy; caching it would not satisfy the separate requirement for fresh evidence, decision, and reasons each cycle. This paper contains no evidence about such a policy.

Training from scratch remains a separate problem. Synthetic maps and conventional planners could supply geometric supervision as a research option, but this paper does not demonstrate that such supervision teaches visual grounding, language, traffic prediction, or faithful reasons in a randomly initialized model.

## 7. Algorithm / pseudocode

The following is a language-agnostic reading of the paper, not an implementation specification that resolves its ambiguities:

1. Supply the start, goal, and known obstacle geometry to the LLM and obtain a waypoint sequence.
2. Insert missing endpoints and remove waypoints inside obstacles, as described in Section 3.2.
3. Initialize the frontier with the start, an empty CLOSED set, start cost zero, and a current target.
4. Remove the state with minimum current priority. If it is the goal, reconstruct a path through stored parents.
5. For each neighbor, apply the paper's target-switch check. When it matches the current non-goal target, advance the target and recompute frontier priorities.
6. Skip neighbors already CLOSED or marked as obstacles. Relax the remaining neighbors' costs and parents, adding the waypoint-distance term to their priorities.
7. Continue until a path is returned or the frontier is exhausted.

The language-model inference cost, graph exploration, collision tests, and all target-triggered queue maintenance belong in the runtime account. A deterministic tie rule, reachable-waypoint matching rule, transition validation, and timeout/failure behavior would need to be specified before an implementation could be treated as a complete engineering design.

## 8. Example calculations

**A. Correct percentage interpretation.** For the strongest Table 1 variant, $100-44.59=55.41$% fewer operations and $100-64.02=35.98$% less reported search storage. Relative path excess is $102.47-100=2.47$%. The reciprocal operation ratio is about 2.2426553; it is only an idealized search-work factor, not a measured runtime speedup.

**B. Admissibility counterexample.** With state $(0,0)$, goal $(10,0)$, and target $(5,0)$ on an obstacle-free line, $h^\star=h=10$, $d_t=5$, and $h_{\rm eff}=15>10$. With target equal to goal, $h_{\rm eff}=20$. For the one-unit edge to $(1,0)$, the consistency right-hand side is $1+18=19<20$.

**C. Timing break-even.** Assume, only for illustration, ordinary search takes 4 ms, guided search time scales exactly with the paper's 0.4459 operation ratio, and common stages are unchanged. Guided search then takes $4\times0.4459=1.7836$ ms, saving 2.2164 ms. Learned guidance plus extra updates must cost less than 2.2164 ms for a net improvement. If guidance alone takes 6 ms, the hybrid takes at least 7.7836 ms before the common stages, so it is slower than the 4 ms baseline despite fewer search operations. These numbers are not Thor measurements.

**D. Geometric aggregation.** Per-task ratios 0.25 and 1 have geometric mean $\exp[(\log0.25+\log1)/2]=0.5$. The reported aggregate is 50%, although one task has no improvement. The arithmetic mean would be 62.5%. Neither aggregate establishes a per-task deadline.

## 10. Potential mathematical risks

### Evidence and reporting limits

1. **Search counts are not end-to-end latency.** The number and cost of LLM tokens, prompt processing, parsing, rekey operations, and total system memory are not characterized sufficiently to establish deployment speed. An 8B model's weights are not included by showing a smaller search frontier.
2. **Validity is an empirical benchmark result.** The reported 100% does not establish validity for arbitrary maps, uncertain perception, dynamic traffic, finite vehicle footprints, or deadline-truncated search. The 1,000 tasks also share only 100 maps, so treating them as independent samples for a reliability claim would be unjustified without further analysis.
3. **No shortest-path guarantee.** Appendix A explicitly acknowledges this. Around 90% optimal paths does not bound the cost of the other paths, and a geometric-mean path ratio conceals tail behavior.
4. **Scaling claims exceed what the plot proves.** Figure 3 has a limited scale range and reports means from 10 trials, without a demonstrated asymptotic proof. Coordinate-scale growth must be distinguished from growth in the number of graph states.
5. **Prompt comparisons are confounded.** Few-shot uses five demonstrations while CoT/RePE use three; prompt length, content, and waypoint choices also differ. The table does not establish that additional reasoning intrinsically harms planning.
6. **Generalization remains unmeasured for Viktor.** Manually selected synthetic static maps, two pretrained LLMs, and coordinate/text inputs do not establish camera or highway performance. There is no from-scratch training recipe, dataset-size scaling law, Thor test, or control-loop evaluation.
7. **No reason-faithfulness evidence.** RePE's generated self-evaluation is not an external geometric check. The study does not test whether explanations are grounded, calibrated, causally responsible for decisions, or consistent with the returned path.
8. **A stronger classical baseline matters.** Dynamic weighted A* obtains 60.91% operations, 78.53% storage, and only 100.24% relative path length without LLM guidance. LLM-A* reduces search counts further in its best settings, but this comparison reinforces the need to include model overhead and path-quality tradeoffs.

### Paper inconsistencies and underspecified details

- Section 4.4 calls 44.59% and 64.02% reductions. Table 1 and the metric definition make them remaining-resource ratios; the corresponding reductions are 55.41% and 35.98%. The introductory suggestion that both resources fall below roughly half the baseline is not supported by the best Table 1 storage ratio of 64.02%.
- Appendix D.3 says a geometric mean greater than one is better. For the proposed/baseline ratios of operations, storage, and path length used in Table 1, smaller is better. Section 4.3 and the table arrows supply the applicable direction.
- Algorithm 1 calls the LLM with an `O` argument while the required obstacle input is named `obs`; the text also uses similar notation for OPEN. The intended map input is explained in prose, but the pseudocode notation is inconsistent.
- The prose refers to Algorithm 1 line numbers that do not exactly match the printed placement of its target-switch and priority equations.
- The target list must contain the start, but initialization selects its start entry. The code-like listing does not clarify skipping an already reached start target. Target advancement occurs when a neighbor equals the target, before the CLOSED/obstacle skip, rather than when the target is popped or physically visited. Discovery, expansion, and actual traversal should not be conflated.
- A continuous-coordinate waypoint may never exactly equal a discrete neighbor. Out-of-bounds, duplicate, unreachable, and malformed outputs are not given complete handling rules. Removing obstacle-contained points alone is insufficient.
- CLOSED states are not reopened, while the target-dependent heuristic may be inconsistent and changes during search. This blocks a casual transfer of ordinary A* optimality arguments.
- The listing checks neighbor membership in obstacles but does not explicitly specify edge-intersection checks or corner-cutting rules. This is a specification gap, not a claim that the released implementation necessarily omits them.
- Figure 4 uses a Chebyshev heuristic in an 11 by 11 grid, while much of the main discussion uses Euclidean distance. Admissibility depends on the chosen neighbor and edge-cost model; these metrics are not interchangeable without checking that model.

The ACL record links software and data. This review reads the paper and its figures; it does not audit those artifacts or rerun the experiments. Implementation details that might resolve the above ambiguities remain unverified.

## 11. Results in limiting / edge cases

| Case | Mathematical consequence | Interpretation |
|---|---|---|
| Waypoint term deliberately set to zero | $f_H=g+h$ | Recovers ordinary A* priority, subject to its usual implementation assumptions |
| Current target equals goal, matching Euclidean terms | $f_H=g+2h$ | Does not recover ordinary A*; can overestimate |
| Current target equals current state | Waypoint term is zero at that state only | No global optimality conclusion follows |
| Current target differs from goal | Combined heuristic can be positive at the goal | Admissibility can fail even at the goal state |
| Poor or unreachable waypoint | Priority may favor irrelevant states | Positive search savings are not guaranteed |
| No usable intermediate waypoints | A target/fallback policy is required | Retaining the goal term and disabling guidance are different algorithms |
| Start equals goal | Correct path length is zero | Search can return immediately, but length ratios against zero are undefined |
| Disconnected goal | Frontier can eventually be exhausted on a finite graph | No-path output is required; an LLM cannot create connectivity |
| Collision-free waypoint endpoints, blocked segment | Vertex tests pass while the connection fails | Continuous transition checks remain necessary |
| Extra inference time exceeds saved search time | R5 fails | Fewer search operations produce a slower full planner |
| Baseline search already very fast | Allowable guidance overhead approaches zero | A large guidance model is harder to justify on latency grounds |

## Further mathematical discussion: a conditional bound on waypoint bias

Added 2026-10-03. **This is our derivation for a specified reopening variant, not a theorem claimed by the LLM-A* paper.** It refines the earlier optimality critique: loss of exact optimality does not by itself rule out a bound on suboptimality. Conditions for retaining such bounds depend on the search mechanics; see [Chen and Sturtevant, IJCAI 2019](https://www.ijcai.org/proceedings/2019/0170.pdf) for background on the role of re-expansions. That source is background, not attribution for the derivation below.

Let $q$ denote the fixed goal, $t$ the current guide, and $d(a,b)=\lVert p(a)-p(b)\rVert_2$ the Euclidean distance in meters. Let $g(s)$ be the discovered start cost, $g^\star(s)$ the optimal start cost, $h^\star(s)$ the optimal remaining cost, $C^\star$ the optimal complete path cost, and $C_{\rm return}$ the reconstructed path cost, all in meters. A proposed global guidance weight $\lambda\in[0,1]$ is dimensionless. It is a design variable for discussion; the existing pseudocode has not been changed to introduce it.

Assume a finite frozen graph with positive edge costs satisfying $c(u,v)\ge d(u,v)$, a reachable fixed goal, complete valid-successor expansion, reopening on every strict improvement to a CLOSED state's cost, exact rekeying of OPEN after every guide change, and no pruning that removes the optimal-path frontier. The goal is accepted when popped at minimum priority, not merely when generated. The argument uses exact arithmetic and applies to a completed goal return, not a deadline/expansion-limit failure.

**1. Interpret the guide as a tunable bias.** Consider

$$
f_{\lambda,t}(s)=g(s)+d(s,q)+\lambda d(s,t).
\tag{D1}
$$

At a given selection step, subtracting the same constant $\lambda d(q,t)$ from every priority preserves the queue ordering. Define the normalized heuristic

$$
\widetilde h_{\lambda,t}(s)
=d(s,q)+\lambda\bigl[d(s,t)-d(q,t)\bigr].
\tag{D2}
$$

This subtraction is a proof device; it is not an additional operation required in the implementation. Unlike the raw combined heuristic, the normalized heuristic is zero at the goal.

**2. Bound it using the triangle inequality.** The reverse triangle inequality gives

$$
-d(s,q)\le d(s,t)-d(q,t)\le d(s,q).
$$

Multiplying by nonnegative $\lambda$ and adding $d(s,q)$ yields

$$
\begin{aligned}
0\le(1-\lambda)d(s,q)
&\le\widetilde h_{\lambda,t}(s)\\
&\le(1+\lambda)d(s,q)\\
&\le(1+\lambda)h^\star(s).
\end{aligned}
\tag{D3}
$$

The last inequality follows from the edge-cost lower bound and repeated triangle inequalities along every graph path. It does not require a correct or reachable guide. When guidance is disabled, using $d(s,q)$ alone also satisfies the same upper bound.

**3. Transfer the heuristic bound to a returned-path bound.** Reopening improved states preserves an OPEN state $v$ on an optimal path with $g(v)=g^\star(v)$ until the goal is selected. Initially this state is the start. Whenever such a state is expanded with its optimal cost, relaxing its next optimal-path successor creates or preserves an optimal-cost frontier state; a previously expanded successor with a worse cost is reopened. This reasoning is independent of the guide-selection sequence.

At goal selection, all OPEN priorities must use the same current guide. Minimum-priority selection and the zero normalized goal heuristic imply

$$
\begin{aligned}
C_{\rm return}
&\le g(q)\\
&\le g^\star(v)+\widetilde h_{\lambda,t}(v)\\
&\le g^\star(v)+(1+\lambda)h^\star(v)\\
&=(1+\lambda)C^\star-\lambda g^\star(v)\\
&\le(1+\lambda)C^\star.
\end{aligned}
\tag{D4}
$$

The first inequality assumes valid parent reconstruction; predecessor cost improvements can make the actual reconstructed length smaller than a stored downstream cost. Recompute the returned path's actual cost. Exact queue rekeying is essential when targets change. Reopening is sufficient for this optimal-cost frontier proof; it is not claimed to be necessary for every possible proof.

**A separate no-reopening argument under the same metric assumptions.** Write $w=1+\lambda$ and $H_t(s)=d(s,q)+\lambda d(s,t)$. Triangle inequalities imply $H_t(u)-H_t(v)\le w\,c(u,v)$ on every edge, for every current target. Suppose CLOSED only grows and all earlier expanded states satisfy $g(p)\le w g^\star(p)$. For the next selected state $n$, take the first not-yet-CLOSED state $x$ on an optimal start-to-$n$ path. Its predecessor's completed relaxation ensures $g(x)\le w g^\star(x)$ and $x$ remains in OPEN. The start supplies the base case. Using current, uniformly rekeyed priorities and summing the edge inequality along the remaining optimal-path segment gives

$$
\begin{aligned}
g(n)
&\le g(x)+H_t(x)-H_t(n)\\
&\le w g^\star(x)+w\bigl[g^\star(n)-g^\star(x)\bigr]\\
&=w g^\star(n).
\end{aligned}
\tag{D5}
$$

This establishes the induction, including the goal. Thus the distance-based no-reopening variant can also have the $(1+\lambda)$ bound if those stronger metric, queue, successor, and cost-record contracts hold. Non-reopening alone is not a counterexample to this bound. The paper does not supply this theorem or fully establish all those contracts across its settings. The pseudocode's selected reopening policy remains unchanged; whether its extra work is worthwhile is a separate benchmark question.

**Interpretation.** With $\lambda=0$, the method reduces to A*. With $\lambda=1$, the distance-based reopening variant has the conditional bound $C_{\rm return}\le2C^\star$. With $\lambda=0.2$, it has the conditional bound $C_{\rm return}\le1.2C^\star$. These are worst-case upper bounds under the assumptions, not predicted path lengths, selected deployment weights, or runtime bounds.

**Checked boundary examples.** For $s=(0,0)$ and $q=(10,0)$, $d(s,q)=10$. At $\lambda=0.2$, the normalized heuristic is 12 when $t=q$, 8 when $t=s$, and 10 when $t=(5,0)$. At $\lambda=1$, the corresponding values are 20, 0, and 10. At $s=q$ it is always zero. These values were checked with an ephemeral standard-library arithmetic calculation; no search implementation was executed. For the displayed scalar examples, absolute tolerance $10^{-12}$ is sufficient.

**Limits for Viktor.** This is a bound on graph path cost. It does not establish collision avoidance under uncertain perception, dynamic traffic feasibility, following quality, or 20-30 ms completion. A different cost in seconds, energy units, or mixed penalties needs compatible metric lower bounds and a new dimensional check. Goal regions, graph merging, beam pruning, approximate queues, and unverified finite-precision behavior require separate analysis. The paper's baseline comparison should also include weighted A* at a matched quality bound: the relevant experiment is whether learned directional guidance improves search time after counting inference and queue-update costs.
